h2. User Story

As a clinician using the header of the scanning application, I want to reach secondary actions (starting a new design, opening the current design in Canvas, or finishing and closing the session) from a compact overflow menu, so that the primary header stays uncluttered while these actions remain reachable.


h2. Design Definition & Assets

- Figma Link: [Header Menu More|https://www.figma.com/design/oY2AELOxR8s6HKYkCTAOQs/Equipment-Components?node-id=4806-26687]
- Design Definition (Jira): [S3806-6113|https://jira.dentsplysirona.com/browse/S3806-6113] — status *Draft*.
- Flutter Component: [header_menu_more.dart|https://github.com/ds-thomasja/di-scan/blob/main/lib/components/header_menu_more/header_menu_more.dart]
- Interaction Model: The More button is a kebab (three vertical dots) icon button in the header, built on {{DSActionsButton.iconTertiary}}. Tapping it opens a popup menu anchored to the button (preferred bottom-right, falling back to top-right if there is insufficient space below), listing three actions in a single section: "Create design", "Open in Canvas", "Finish and close". Selecting an action closes the popup first, then invokes that action's callback ({{onCreateDesign}} / {{onOpenInCanvas}} / {{onFinishAndClose}}) — the component itself does not perform navigation or any side effect; the host app owns what each action actually does. The popup also closes on an outside tap. While the popup is open, the button shows a pressed/"open" look. The button carries a "More" tooltip.


h2. Component Props

|| Prop || Type || Default || Description ||
| {{onCreateDesign}} | {{VoidCallback?}} | {{null}} | Called when "Create design" is selected. If {{null}}, the component substitutes a no-op callback internally, so the option still renders *enabled* (hover/pressed states remain testable) — selecting it just closes the popup and does nothing further. |
| {{onOpenInCanvas}} | {{VoidCallback?}} | {{null}} | Called when "Open in Canvas" is selected. Same no-op fallback as above when {{null}}. |
| {{onFinishAndClose}} | {{VoidCallback?}} | {{null}} | Called when "Finish and close" is selected. Same no-op fallback as above when {{null}}. |

h2. Acceptance Criteria

 - *Functional:*
 -- Tapping the trigger button opens the popup menu; tapping it again, tapping outside the popup, or selecting any option closes it.
 -- Selecting "Create design" closes the popup and then invokes {{onCreateDesign}}; the same close-then-invoke order applies to "Open in Canvas" ({{onOpenInCanvas}}) and "Finish and close" ({{onFinishAndClose}}) — confirmed from {{DSActionsButton}}'s own {{onChanged}} handler ({{closePopup(); value.onTrigger?.call();}}).
 -- Any option whose callback is {{null}} (the default for all three) still renders *enabled*: {{header_menu_more.dart}} passes {{onCreateDesign ?? () {}}} (and the equivalent for the other two) as {{onTrigger}}, so {{DSAction.toOption()}}'s {{enabled: onTrigger != null}} rule is always satisfied and the row responds to hover/pressed/tap — tapping it with no host callback wired just closes the popup and performs no action.
 -- The three options always render in a single, undivided section, in the fixed order Create design → Open in Canvas → Finish and close.
 -- The component performs no navigation, snackbar, or other side effect itself — all three actions are purely host-owned callbacks (*confirm with Product* whether "Create design" / "Open in Canvas" / "Finish and close" are expected to navigate, and to where; not specified by the Figma node itself).

 - *Tooltip:*
 -- The trigger button shows a "More" tooltip, using {{DSActionsButton}}'s built-in {{tooltip}} parameter (default DS tooltip behavior/timing — not overridden by this component).

 - *States:*
 -- Trigger button, default: transparent background.
 -- Trigger button, hovered: {{var(--action-tertiary/hovered)}} background (exact token confirmed via source; hex not present in the Figma node's exported variables — *confirm exact color with Design if needed*).
 -- Trigger button, pressed / popup open: {{var(--action-tertiary/pressed, rgba(0,0,0,0.16))}} background — confirmed against both the Figma node's exported variables and {{DSCrudeButtonThemeData.tertiary}}'s source.
 -- Option row, default: {{var(--surface/standard, #ffffff)}} background (per {{DSOptionThemeData}}; hover/pressed row backgrounds are DS-internal and not independently re-verified here).
 -- Option row, with no host callback wired: renders identically to the enabled/default state above — this component never lets a row reach DS's disabled treatment, since the no-op fallback always keeps {{onTrigger}} non-null.

 - *A11y:*
 -- Keyboard navigation between options (arrow keys) is handled internally by {{DSFocusable}}/{{DSOptionWrapper}}; not independently re-verified here.
 -- Focus visibility on each option row uses {{DSFocusBorder}} (inner focus border), per DS internals.
 -- No additional ARIA/semantics labels are specified by the Figma node itself; the component relies entirely on {{DSActionsButton}}/{{DSOptionList}}'s own built-in accessibility behavior — *not independently audited here, recommend a dedicated a11y pass if required for release*.

 - *Visual Fidelity:*
 -- *Trigger icon button:*
 --- Sizing: 24x24 px icon ({{DSIcons.dotsVertical}}, {{var(--icon/size/m)}} = 24 px), inside 8 px padding on all sides ({{var(--spacing/component/xs)}}) — 40x40 px effective tap target.
 --- Icon color: {{var(--icon/standard, #242424)}}.
 --- Border-radius: {{var(--border/radius/standard, 12px)}}.
 -- *Popup menu container:*
 --- Sizing: intrinsic width (sized to the widest option label, "Finish and close" — *not* a fixed px value; the 114 px seen in the Figma export is a snapshot of that specific render, not a design constant).
 --- Background: {{var(--surface/standard, #ffffff)}}.
 --- Border-radius: {{var(--border/radius/standard, 12px)}}.
 --- Shadow: {{var(--shadows/elevation-3)}} = x 0 px, y 4 px, blur 20 px, spread 6 px, color {{rgba(0,0,0,0.08)}}.
 --- Padding: {{var(--spacing/component/xs, 8px)}} top and bottom; 0 left/right (the horizontal inset lives on each option row instead).
 --- Position: anchored to the trigger button, preferred bottom-right, falling back to top-right when there isn't room below (fixed {{DSActionsButton}} behavior, not overridden here).
 -- *Option row ("Create design" / "Open in Canvas" / "Finish and close"):*
 --- Padding: {{var(--spacing/component/xs, 8px)}} top/bottom, {{var(--spacing/component/m, 16px)}} left/right.
 --- Gap between icon and label: {{var(--spacing/component/xs, 8px)}}.

 --- Label: Be Vietnam Pro, 16 px / 24 px line-height / -0.4 px letter-spacing, {{var(--text/standard, #242424)}} (Regular weight — the {{Text/textBase}} style, confirmed via the Figma node's exported variables).


h2. Content Logic & Edge Cases

- *No action wired (all three callbacks {{null}}, the widget's default):* the popup still opens and shows all three rows, all *enabled* — deliberately so, so hover/pressed states stay testable even with nothing wired up. Selecting a row with no host callback simply closes the popup; no navigation, snackbar, or other side effect occurs, since there is nothing to run in the background. The component never hides or disables an option just because its callback is unset. *Confirm with Design/Product whether this is the intended empty-state behavior*, since the Figma node itself only documents the fully-wired state.
- *Label truncation:* none of the three labels are expected to overflow at their fixed English copy; no ellipsis/wrap behavior is specified or was exercised in the Figma export.
- *Popup width vs. viewport edge:* not a real risk — confirmed against {{DSActionsButton}}'s source (via {{DSModalPopupAnchor}} → {{DSPopupLayoutDelegate}}/{{calculatePopupRect}}), which clamps the popup's position against the full screen bounds (inset by {{screenPadding}}, default {{var(--spacing/layout/xs)}}), not just the local header width. Even with a very narrow header and the button near the edge, the popup slides horizontally as needed to stay fully on-screen instead of being clipped.


h2. Responsiveness & Links
