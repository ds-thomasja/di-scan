h2. User Story

{Draft: As a clinician using the scanning application, I want to see the connected scanner's name, network and battery status at a glance from the header, and switch to a different scanner without leaving the current screen, so that I can confirm my equipment is ready without interrupting my workflow.} — not confirmed with Product.


h2. Design Definition & Assets

- Figma Link: [Header Menu Device|https://www.figma.com/design/oY2AELOxR8s6HKYkCTAOQs/Equipment-Components?node-id=4457-15146]
- Design Definition (Jira): TBD — no ticket identified in this session (no Jira/Atlassian access available). Confirm with the team whether one exists, similar to the sibling menus' tickets (e.g. HeaderMenuSettings' S3806-6118).
- Flutter Component: [header_menu_device.dart|https://github.com/ds-thomasja/di-scan/blob/main/lib/components/header_menu_device/header_menu_device.dart]
- Interaction Model: {{HeaderMenuDevice}} is a header-bar trigger button with two content modes selected by whether {{device}} (a {{HeaderMenuConnectedDevice?}}) is {{null}}. When {{null}} ("no scanner selected"), the trigger shows a {{DSIcons.warning}} icon plus a label that shrinks with viewport width ("Select scanner" → "Scanner" → icon-only) and calls {{onSelectScanner}} on tap; there is no dropdown panel in this mode, matching the Figma node's absence of an Open=true variant for {{Scanner=false}}. When {{device}} is set, the trigger shows (viewport-dependent) the device name, a Wi-Fi icon, and a {{DSBatteryIndicator}}, and tapping it opens a detail panel via {{DSModalPopupAnchor}} (preferred bottom-right, falling back to bottom-left then top-right), anchored under the button. The panel lists a Name row, a WiFi row (if {{device.wifiName}} is set) and a Battery row (if {{device.batteryPercent}} is set), each optionally followed by a {{DSInlineNotification}} warning ("Unstable connection" / "Troubleshoot" for network, "Low battery" / "Switch scanner" for battery) when the corresponding {{*WarningMessage}} prop is non-null, and a "Change device" row at the bottom when {{hasMultipleDevices}} is true. The trigger keeps a pressed look ({{DSClickableState.pressed}}) for the panel's whole open lifetime, matching {{HeaderMenuSettings}}. Three optional 8×8 {{DSBadge}} dots ({{hasNetworkAlert}} = warning, {{hasBatteryAlert}} = critical, {{hasCalibrationDue}} = information) can be pinned to the trigger's top-right corner independent of viewport or open state.

h2. Acceptance Criteria

 - *Functional:*
 -- When {{device}} is {{null}}, the trigger shows a warning icon and a label that shrinks with viewport ("Select scanner" → "Scanner" → none); tapping it calls {{onSelectScanner}} and opens no panel.
 -- When {{device}} is set, tapping the trigger opens a detail panel via {{DSModalPopupAnchor}} (preferred bottom-right, falling back to bottom-left then top-right); tapping outside the panel closes it (native {{DSModalPopupAnchor}} dismissal).
 -- The panel always lists Name first, then WiFi (if {{device.wifiName != null}}), then Battery (if {{device.batteryPercent != null}}), then "Change device" (if {{hasMultipleDevices}}), each pair separated by a horizontal divider — a divider only renders between two sections that are both actually visible.
 -- {{onChangeDevice}}, {{onTroubleshootNetwork}} and {{onSwitchScanner}} each close the panel first, then invoke the host callback.
 -- {{networkWarningMessage}} is ignored (no notification shown) when {{device.wifiName}} is {{null}}; {{batteryWarningMessage}} is ignored when {{device.batteryPercent}} is {{null}}.
 -- A non-null {{networkWarningMessage}} (or {{hasNetworkAlert}}) also switches the Wi-Fi icon (trigger and panel) from {{DSIcons.wifiHigh}} to {{DSIcons.wifiLow}}.
 -- The panel's Battery row icon switches between {{DSIcons.batteryFull/High/Mid/Low/Empty}} by percent threshold, and turns {{tokens.icon.critical}} at or below {{lowBatteryThreshold}}.

 - *States:*
 -- Trigger button, default/hover/focus/pressed: {{DSCrudeButtonThemeData.tertiary}}'s built-in backgrounds — not independently re-verified pixel-by-pixel here.
 -- Trigger button stays in its pressed look ({{DSClickableState.pressed}}) for the panel's entire open lifetime, not just the initial tap — same treatment as {{HeaderMenuSettings}}.
 -- Panel background: {{var(--surface/standard, #ffffff)}}.

 - *Tooltip:*
 -- At the S breakpoint only, the trigger shows a tooltip: "Select scanner" in prompt mode, or the device's name in connected mode. Not shown at M/">L" since the visible label already conveys this — *this tooltip behavior is an implementation addition, not something the Figma node itself specifies; confirm with Design that it's wanted.*

 - *A11y:*
 -- Each corner badge is wrapped in {{Semantics}} with an explicit label ("Network alert" / "Battery alert" / "Calibration due") since the badge itself is a bare colored dot with no visible text.
 -- Keyboard/focus behavior for {{DSCrudeButton}}/{{DSModalPopupAnchor}}/{{DSInlineNotification}} is DS-internal — not independently re-verified here.

 - *Visual Fidelity:*
 -- *Trigger button:*
 --- Padding: {{var(--spacing/component/m, 16px)}} horizontal, {{var(--spacing/component/xs, 8px)}} vertical, at every breakpoint including the icon-only S layout (taken literally from the Figma spec, not re-derived per breakpoint).

 --- Border-radius: {{var(--border/radius/standard, 12px)}}.

 --- Label typography: {{tokens.text.textAction}} (Be Vietnam Pro SemiBold, 14px / 24px line-height / -0.35px letter-spacing), matching the Figma node's {{Text/textAction}} for the "Select scanner"/"Scanner"/device-name label. h2. Content Logic & Edge Cases

- *No scanner connected:* {{device == null}} suppresses the entire panel/open behavior — there is no Figma "Open=true" variant for {{Scanner=false}}, so this is a hard functional gap, not a visual-only difference.
- *Missing WiFi/battery data:* {{wifiName}}/{{batteryPercent}} being {{null}} independently omits its own trigger element (battery indicator only) and panel row+warning — the two are not coupled to each other or to {{device.name}}.
- *No composable DS list-item primitive:* the panel's Name/WiFi/Battery rows are hand-rolled ({{_DetailRow}}) rather than built on {{DSListItem}}, since that DS widget targets {{DSList}} rows and didn't fit this icon+headline+subtext shape without fighting its own layout — same category of judgment call as {{DeviceCard}}'s composition history in the sibling {{overarching}} app.
- *Narrow-window battery clipping:* {{DSBatteryIndicator}} reads the *real* {{DSFormFactor.of(context)}} itself (not the {{formFactor}} override) and hides its percentage text below the small-breakpoint window width — so forcing {{formFactor: DSFormFactor.medium}} in an actually-narrow browser window can show the battery icon without its percentage, even though the M breakpoint is documented as icon+percentage. This is existing {{lightning_core_ui}} v51 behavior, not a bug introduced by this component.
- *Panel width vs. viewport edge:* the panel has three fallback positions (bottom-right → bottom-left → top-right) so it should stay on-screen at typical header widths; not independently verified at extreme viewport sizes.


h2. Responsiveness & Links

- Three breakpoints via {{DSFormFactor.of(context)}} (overridable via {{formFactor}} for preview/testing): {{small}} → icon-only trigger (warning or Wi-Fi icon, no text, no battery); {{medium}} → icon + battery (icon+%) or icon + "Scanner", no device name; {{large}}/{{extraLarge}} → full label (device name or "Select scanner") + icon + battery. The panel itself does not change with viewport.
