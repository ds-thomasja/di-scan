h2. User Story

{Draft: not yet confirmed with product} As a clinician, I want to see clear progress feedback while the scan application is preparing, so that I know the system is working and can cancel the attempt if it is taking too long.

h2. Design Definition & Assets

- Figma Link: [Application loading|https://www.figma.com/design/oY2AELOxR8s6HKYkCTAOQs/Equipment-Components?node-id=5033-19060]
- Flutter Component: [application_loading.dart|https://github.com/ds-thomasja/di-scan/blob/main/lib/components/application_loading/application_loading.dart]
- Interaction Model: A single, mostly-static full-screen state (1600×1024 in Figma) shown while a scan is being prepared. It always shows an indeterminate progress circle with the scanner device illustration, a "Loading scan..." heading, and a subtext line. Two blocks are conditionally shown based on props: an info-style inline notification ({{notification}}) explaining a slower-than-usual load, and a 3-step timeline card ({{timeline}}) showing "Preparing workspace…" (active) → "Fetch scan data" (upcoming) → "Start application" (upcoming). A tertiary "Cancel loading" button is always shown and calls {{onCancel}} when pressed; there is no confirmation step and no other navigation target defined at this component's level (what happens after cancel — e.g. which screen is shown next — is out of scope for this component and owned by the caller). No Figma-defined motion exists for this node (confirmed via `get_motion_context`); the progress circle's indeterminate rotation is inherent behavior of the DS {{DSProgressCircleFilled}} widget itself, not a custom animation authored for this component.

h2. Component Props

|| Prop || Type || Default || Description ||
| {{notification}} | {{bool}} | {{true}} | Shows/hides the "Taking a little longer than usual" inline notification. |
| {{timeline}} | {{bool}} | {{true}} | Shows/hides the 3-step timeline stepper card. |
| {{onCancel}} | {{VoidCallback?}} | {{null}} | Called when "Cancel loading" is pressed. The button stays enabled when {{null}}; pressing it is then a no-op. |

h2. Acceptance Criteria

 - *Functional:*
 -- The {{notification}} prop controls visibility of the "Taking a little longer than usual" inline notification; hidden when {{notification = false}}.
 -- The {{timeline}} prop controls visibility of the 3-step timeline card; hidden when {{timeline = false}}.
 -- Pressing "Cancel loading" invokes {{onCancel}} if provided; the button remains enabled and tappable even when {{onCancel}} is {{null}}, in which case pressing it is a no-op.
 -- The progress circle, scanner illustration, heading, and subtext are always shown regardless of prop values.

 - *States:*
 -- Single visual state — content is driven entirely by {{notification}}/{{timeline}}; there is no hover/selected/disabled variant of the component itself (the wrapped {{DSButton.tertiary}} and {{DSInlineNotification}} own their own internal interactive states).

 - *A11y:*
 -- Touch target size, focus outline, and contrast for the Cancel button and inline notification icon are owned by the underlying {{DSButton}}/{{DSInlineNotification}} DS widgets and are not independently overridden here.

h2. Content Logic & Edge Cases

- *Both optional blocks off*: with {{notification = false}} and {{timeline = false}}, the layout collapses to just the progress circle, heading, subtext, and Cancel button — no placeholder space is reserved for the hidden blocks.
- *Short viewport*: unlike the Figma frame (which is a fixed 1600×1024 desktop composition), the shipped implementation wraps its content in a scroll view so the whole block degrades to vertical scrolling once the available height is smaller than the content — this is an engineering addition beyond what Figma specifies, not a designed behavior (confirm with Design whether a shorter/responsive variant should instead be designed explicitly).
- *No dynamic copy*: all strings (heading, subtext, notification title/body, step labels, button label) are static — there is no interpolated wait-time estimate or step count in the current Figma copy (contrast with an earlier internal prototype of this screen, which had a bracketed "[estimated time]" placeholder in the notification body; that placeholder is not present in this Figma source of truth).
- *{{onCancel}} is {{null}}*: the button still renders enabled and tappable; pressing it is a no-op rather than being visually disabled — {confirm with Design/Product whether the button should instead be disabled or hidden when no cancel action is available}.
