User story

As a clinician waiting for the DI scan software to load, I want the loading screen to tell me how much longer to expect and what is happening, so that I know the system is still working and don't restart the process unnecessarily

Component Props
Prop	Type	Default	Description
subline	String	"This may take a few seconds"	Subtext shown under the heading. Swapping it cross-fades in place at a constant height if the new text wraps to the same number of lines as the old; if the line count changes, the swap also animates height (see Motion below).
notification	bool	true	Shows/hides the "Taking a little longer than usual" inline notification. Fixed copy — the component has no warning/timeout variant.
timeline	bool	true	Shows/hides the 3-step timeline card. The 3 steps are fixed content (see States below) — the component does not accept per-step state as input.
onCancel	VoidCallback?	null	Called when "Cancel loading" is pressed. The button stays enabled when null; pressing it is then a no-op.
Acceptance Criteria
Functional:
The page renders a Title ("Loading scan..."), an Indeterminate progress circle, and a "Cancel loading" action at all times.
`notification` and `timeline` are independent booleans set by the caller — the component itself does not enforce any mutual exclusivity between them and the subline (see Design Intent below for the intended caller-side behavior).
Activating "Cancel loading" exits the loading page (behaviour target: page where DI Scan was started from).
States — Timeline stepper (fixed content, not configurable via props):
Infrastructure: icon Stepper-Active (filled), text "Preparing workspace…" — always shown as the active step.
Scan data: icon Circle (empty), text "Fetch scan data" — always shown as an upcoming step.
Application: icon Circle (empty), text "Start application" — always shown as an upcoming step.
Motion:
The `notification` and `timeline` show/hide transitions, and the `subline` text swap, use a 320ms opacity/height transition with an easeInOutSine curve (softer than the Figma spec's 200ms cubic-bezier(0.4, 0.0, 0.2, 1) — a deliberate implementation choice for a gentler feel; not pixel/timing-identical to Figma).
The height component of the subline's transition only applies when its wrapped line count actually changes (e.g. wrapping to a different number of lines); a swap between two same-line-count strings (e.g. "This only takes a moment" → "Ready in about 30 seconds") cross-fades in place at a constant height, with no height animation.
Design Intent — not implemented in this component (caller-owned behaviour for whoever assembles the real loading page; documented here as the target design, since it motivated the `subline`/`notification`/`timeline` props):
Exactly one of {Subline + Timeline stepper} OR {Inline notification} is intended to be visible at any time — never both, never neither — by driving `notification`/`timeline` accordingly; the component does not enforce this itself.
Elapsed time since load start is intended to drive `subline` through: "Checking wait time..." (waiting for estimate) → "This only takes a moment" (0–10s) → "Ready in about 30 seconds" (10–45s) → "Ready in about a minute" (45–80s) → "Ready in about 2 minutes" (80s–2.5min) → beyond 2.5min, set `notification = true` and `timeline = false` instead of a subline (info copy: "Taking a little longer than usual" / "This can take several minutes. Please stay on this screen and do not refresh.").
On a backend-reported timeout, the intended notification copy is a warning variant ("We couldn't finish loading" / "Something went wrong on our side.") — not available today, since `notification`'s type is hardcoded to information.
The 3 timeline steps are intended to be independently driven by backend events (each of Infrastructure/Scan data/Application cycling Pending → Active → Complete, with Application's Complete state visible a minimum of 1500ms) — not available today, since the stepper's 3 steps are fixed content, not props.

Content Logic & Edge Cases
The subline is always rendered regardless of `notification`/`timeline`, and there is no prop to remove it — the Figma instance overrides that remove it entirely once a notification is shown (Design Intent above) are not implemented; a caller wanting that behavior must be given that capability in a future change to this component.
Both optional blocks off: with `notification = false` and `timeline = false`, the layout collapses to the progress circle, title, subline, and Cancel button — no placeholder space is reserved for the hidden blocks.
Step label is single-line; if a future longer label overflows 320px width, truncate with ellipsis (`text-overflow: ellipsis`) rather than wrapping.
