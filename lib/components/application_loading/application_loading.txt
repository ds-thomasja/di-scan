User story

As a clinician waiting for the DI scan software to load, I want the loading screen to tell me how much longer to expect and what is happening, so that I know the system is still working and don't restart the process unnecessarily

Acceptance Criteria
Functional:
The page renders a Title ("Loading scan..."), an Indeterminate progress circle, and a "Cancel loading" action at all times.
Exactly one of {Subline + Timeline stepper} OR {Inline notification} is visible at any time — never both, never neither.
Activating "Cancel loading" exits the loading page (behaviour target: page where DI Scan was started from).
States — Time description (elapsed time since load start):
Waiting for estimate:
Subline: "Checking wait time...".
Timeline stepper visible.
No notification.
0–10s:
Subline: "This only takes a moment".
Timeline stepper visible.
No notification.
10–45s:
Subline: "Ready in about 30 seconds".
Timeline stepper visible.
No notification.
45–80s:
Subline: "Ready in about a minute".
Timeline stepper visible.
No notification.
80s–2.5min:
Subline: "Ready in about 2 minutes".
Timeline stepper visible.
No notification.
>2.5min (still loading):
Subline is removed from the DOM.
Timeline stepper is removed from the DOM.
An info Inline notification appears,
Title: "Taking a little longer than usual"
Body: "This can take several minutes. Please stay on this screen and do not refresh."
Timeout (backend reports the load failed):
Subline is removed from the DOM.
Timeline stepper is removed from the DOM.
A warning Inline notification appears,
Title: "We couldn't finish loading"
Body: "Something went wrong on our side."
Transition between any two time-description states uses a 200ms opacity/height transition, easing cubic-bezier(0.4, 0.0, 0.2, 1). The height component of that transition only applies when the subline's wrapped line count actually changes between the two states (e.g. appearing/disappearing, or wrapping to a different number of lines); a swap between two states whose subline renders as the same number of lines (e.g. "This only takes a moment" → "Ready in about 30 seconds") cross-fades in place at a constant height, with no height animation.
States — Timeline stepper (per-step, driven by backend events, independent of elapsed time):
Each of the 3 steps (Infrastructure, Scan data, Application) has 3 mutually exclusive states: Pending, Active, Complete.
Infrastructure
Pending: icon Circle (empty), text "Prepare workspace".
Active: icon Stepper-Active (filled), text "Preparing workspace…".
Complete: icon Check-Circle-Filled, text "Workspace ready".
Scan data
Pending: icon Circle, text "Fetch scan data".
Active: icon Stepper-Active, text "Fetching scan data…".
Complete: icon Check-Circle-Filled, text "Scan data ready".
Application
Pending: icon Circle, text "Start application".
Active: icon Stepper-Active, text "Starting application…".
Complete: icon Check-Circle-Filled, text "Application ready", visible minimum 1500ms.
Default state on page load:
Infrastructure = Active,
Scan data = Pending,
Application = Pending.
Step order is fixed (Infrastructure → Scan data → Application); steps do not reorder or skip.

Content Logic & Edge Cases
Subline and Inline notification are mutually exclusive — the subline is removed from the DOM entirely (not merely hidden) once the >2.5min or Timeout state is reached, matching the Figma instance overrides for those two states.
Timeline stepper and Inline notification are mutually exclusive — the stepper is removed from the DOM entirely once a notification (info or warning) is shown, per the same Figma instance overrides.
Step label text always reflects the step's current state (Pending / Active / Complete) verbatim per the table above — no other copy variants exist in the supplied design.
Step label is single-line; if a future longer label overflows 320px width, truncate with ellipsis (`text-overflow: ellipsis`) rather than wrapping.
