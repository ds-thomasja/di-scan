User story

As a clinician waiting for the DI scan software to load, I want the loading screen to tell me how much longer to expect and what is happening, so that I know the system is still working and don't restart the process unnecessarily

Component Anatomy & Flutter Mapping
The component renders one of 3 mutually exclusive full-screen compositions, selected via the `state` prop (`ApplicationLoadingState.loading`/`.delayed`/`.timeout`, reconciled against their own dedicated Figma nodes above, 2026-09-30). All 3 share the same progress circle and overall layout shell.
Element	Flutter Widget	Documentation
Indeterminate progress circle	DSProgressCircleFilled.withImage	Progress circle (filled)
Title	Text (style: heading3xl), fixed copy — "Preparing scan..." in `.loading`/`.delayed`, "Couldn't prepare scan" in `.timeout`	n/a
Subline	Text (style: textBase, subdued) — shown only in `.loading` (via the `subline` prop) and `.delayed` (fixed 2-line copy); absent entirely in `.timeout`	n/a
Inline notification	DSInlineNotification — absent in `.loading`; information type, message-only, in `.delayed`; warning type with a "Try again" DSNotificationAction link (via the `onRetry` prop), in `.timeout`	Inline notification
Timeline container	DSContainer — shown only in `.loading`	Container
Timeline stepper	DSTimelineStepper, 3 fixed DSTimelineStep entries (see States below) — shown only in `.loading`	Timeline stepper
Bottom action	DSButton.tertiary, via the `onCancel` prop — labelled "Cancel" in `.loading`/`.delayed`, "Close" in `.timeout`	Button
Component Props
Prop	Type	Default	Description
subline	String	"Takes a few seconds"	Subtext shown under the heading, only when `state` is `.loading`. Swapping it cross-fades in place at a constant height if the new text wraps to the same number of lines as the old; if the line count changes, the swap also animates height (see Motion below). Ignored for `.delayed` (fixed copy) and `.timeout` (no subline).
state	ApplicationLoadingState	.loading	Selects which of the 3 Figma-defined screens to render. The 3 values are mutually exclusive — there is no way to combine or partially apply them.
onCancel	VoidCallback?	null	Called when the bottom button ("Cancel"/"Close") is pressed. The button stays enabled when null; pressing it is then a no-op.
onRetry	VoidCallback?	null	Called when "Try again" is pressed in the `.timeout` notification. Unused in the other two states. Per DSNotificationAction, the link renders disabled when this is null.
Acceptance Criteria
Functional:
The page renders a Title, an Indeterminate progress circle, and a bottom action at all times, across all 3 states.
`state` is the single source of truth for which screen is shown — the component does not expose independent booleans for the notification/timeline/subline, since Figma defines these 3 screens as fixed, non-combinable compositions (see States below).
Activating "Cancel"/"Close" exits the loading page (behaviour target: page where DI Scan was started from). Activating "Try again" (only reachable in `.timeout`) retries loading.
States — the 3 `ApplicationLoadingState` screens (each fully fixed content, confirmed against its own full-screen Figma node, 2026-09-30):
`.loading` (Figma node 5033:19060, via 5025:18863): Title "Preparing scan...", `subline` (caller-driven, see Design Intent for its elapsed-time progression), the 3-step timeline stepper, no notification, button "Cancel".
`.delayed` (Figma node 5025:18764): Title "Preparing scan..." (unchanged from `.loading`), fixed 2-line subline "Takes several minutes.\nThe delay is server-side, not on this device." (the line break is literal, not a wrap), an information notification reading "Keep this screen open. Refreshing restarts loading." (message-only, no title), no timeline, button "Cancel".
`.timeout` (Figma node 5086:23421): Title "Couldn't prepare scan" (distinct from the other 2 states), no subline, a warning notification reading "Server-side issue. Scan data remains safe." plus a "Try again" link action (wired to `onRetry`), no timeline, button "Close" (distinct from "Cancel").
States — Timeline stepper (fixed content, not configurable via props; only rendered in `.loading`):
Infrastructure: icon Stepper-Active (filled), text "Setting up workspace…" — always shown as the active step.
Scan data: icon Circle (empty), text "Scan data" — always shown as an upcoming step.
Application: icon Circle (empty), text "Scanner" — always shown as an upcoming step.
Motion:
The notification/timeline show/hide transitions, and the `subline` text swap, use a 320ms opacity/height transition with an easeInOutSine curve (softer than the Figma spec's 200ms cubic-bezier(0.4, 0.0, 0.2, 1) — a deliberate implementation choice for a gentler feel; not pixel/timing-identical to Figma).
The height component of the subline's transition only applies when its wrapped line count actually changes (e.g. wrapping to a different number of lines); a swap between two same-line-count strings (e.g. "Takes a few seconds" → "Takes under a minute") cross-fades in place at a constant height, with no height animation.
Design Intent — partially caller-owned (behaviour for whoever assembles the real loading page and drives `subline`/`state` over time; the 3 screens themselves are now fully implemented, per States above):
Elapsed time since load start is intended to drive `subline` through (wording reconciled against Figma "Equipment-Components" node 5086:22894, 2026-09-30; the pre-estimate "Checking wait time..." state was not present in that reference and is unconfirmed), while `state` stays `.loading`: "Checking wait time..." (waiting for estimate) → "Takes a few seconds" (0–10s) → "Takes under a minute" (10–45s) → "Takes under 2 minutes" (45–80s) → "Takes under 3 minutes" (80s–2.5min) → beyond ~3 minutes, switch `state` to `.delayed` (its fixed subline/notification copy takes over from here).
On a backend-reported timeout, switch `state` to `.timeout`. This is fully implemented (2026-09-30, including the distinct title, absent subline, warning notification with a working "Try again" link, and "Close" button label) — no longer a partial/unconfirmed variant.
Each of the 3 timeline steps is intended to cycle Pending → Active → Complete with distinct copy per state (Figma node 5086:22916, 2026-09-30), superseding the generic description above:
- Infrastructure step: Pending "Workspace" → Active "Setting up workspace…" → Complete "Workspace ready".
- Scan data step: Pending "Scan data" → Active "Loading scan data…" → Complete "Scan data ready".
- Application step: Pending "Scanner" → Active "Connecting scanner…" → Complete "Scanner ready".
The 3 timeline steps are intended to be independently driven by backend events, with Application's Complete state visible a minimum of 1500ms — not available today, since the stepper's 3 steps are fixed content, not props.

Content Logic & Edge Cases
The 3 `state` values are mutually exclusive by construction (a single enum, not independent booleans) — there is no way to render, say, the timeline alongside the `.timeout` notification, matching the 3 fixed Figma compositions exactly.
`subline` is only read in `.loading`; changing it while `state` is `.delayed`/`.timeout` has no visible effect, since those states use their own fixed (or absent) subline.
Step label is single-line; if a future longer label overflows 320px width, truncate with ellipsis (`text-overflow: ellipsis`) rather than wrapping.
